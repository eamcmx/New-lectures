§ 4

Degrees of freedom & reference frames

To describe whether an object is moving or static, we need a reference — a stationary frame to compare against. We assign a reference frame with three axes $x$, $y$, $z$.

A free body in 3D space has 6 degrees of freedom: three translational (along $x$, $y$, $z$) and three rotational (about $x$, $y$, $z$). If the body also carries its own mobile frame and can rotate/translate within that frame, the system can carry up to 12 degrees of freedom.

For a robot manipulator, we always have two frames in play:

  • Frame 0 — the fixed frame, attached to the base of the robot.
  • Mobile frame — attached to the tool / end-effector.

The restrictions imposed by the links determine how the mobile frame can move relative to the fixed frame. The question for the rest of the course: how do we represent that relationship mathematically?

The answer
Vectors and matrices. Specifically — we project the mobile frame's unit vectors onto the fixed frame's axes.
§ 5

Overlapping frames → the identity matrix

Take a mobile frame with unit vectors $\vec{u}$, $\vec{v}$, $\vec{w}$ overlapping the fixed frame $x$, $y$, $z$. Since the vectors are unitary, each component of $\vec{u}$ on a fixed axis is just how much of $\vec{u}$ projects onto that axis.

When the frames perfectly overlap:

  • $\vec{u} = (1, 0, 0)$ — completely aligned with $x$
  • $\vec{v} = (0, 1, 0)$ — completely aligned with $y$
  • $\vec{w} = (0, 0, 1)$ — completely aligned with $z$

Stacking these as columns gives a 3×3 matrix with ones on the diagonal — the identity matrix $I_3$:

$$I_3 = \begin{bmatrix} 1 & 0 & 0 \\ 0 & 1 & 0 \\ 0 & 0 & 1 \end{bmatrix}$$

This is the rotation matrix that says "the mobile frame has the same orientation as the fixed frame."

If you see $(0, -1, 0)$ for $\vec{u}$, that means $\vec{u}$ points in the opposite direction of $y$. The sign tells you direction; the magnitude tells you projection.

   u  [ 1   0   0 ]
   v  [ 0   1   0 ]
   w  [ 0   0   1 ]
§ 6

Rotation around the X axis

Now rotate the mobile frame by angle $\theta$ about the $x$ axis. Project each mobile unit vector onto the fixed axes:

  • $\vec{u}$ is still aligned with $x$ → $(1, 0, 0)$
  • $\vec{v}$ no longer lies on $y$; it picks up a component on $z$. The projection onto $y$ uses the adjacent side → $\cos\theta$; onto $z$ uses the opposite side → $\sin\theta$. So $\vec{v} = (0, \cos\theta, \sin\theta)$.
  • $\vec{w}$ tilts away from $z$ toward the negative-$y$ direction → $(0, -\sin\theta, \cos\theta)$.

Putting them together:

$$R_x(\theta) = \begin{bmatrix} 1 & 0 & 0 \\ 0 & \cos\theta & -\sin\theta \\ 0 & \sin\theta & \cos\theta \end{bmatrix}$$

This is the basic rotation matrix around X — the first building block of every transformation we'll build.

Sign discipline
The minus sign on $\sin\theta$ comes from $\vec{w}$ projecting onto the negative side of $y$ after the rotation. Get the sign wrong and your whole chain of transforms is wrong.
R_x(theta) layoutlayout
R_x = [  1        0          0     ;
         0   cos(theta)  -sin(theta) ;
         0   sin(theta)   cos(theta) ]

§ 7

MATLAB: drawing the fixed reference frame

MATLAB's line command takes three bracketed pairs — $[x_1, x_2]$, $[y_1, y_2]$, $[z_1, z_2]$ — and draws a 3D segment between them. To draw the three unit axes from the origin:

  • $x$ axis (red): from $(0,0,0)$ to $(1,0,0)$
  • $y$ axis (green): from $(0,0,0)$ to $(0,1,0)$
  • $z$ axis (blue): from $(0,0,0)$ to $(0,0,1)$

We add 'color' and 'LineWidth' attributes to make the axes legible, and set a default 3D viewpoint with view(130, 30). Because we'll need this every session, we save it as a script called fixframe.m and just call fixframe going forward.

fixframe.m — draws the fixed reference framematlab
line([0 1],[0 0],[0 0],'color','r','LineWidth',2);
line([0 0],[0 1],[0 0],'color','g','LineWidth',2);
line([0 0],[0 0],[0 1],'color','b','LineWidth',2);
view(130,30);
§ 8

MATLAB: writing the RotaX function

A script runs the same code every time. A function takes inputs and returns outputs — exactly what we need for $R_x(\theta)$.

The pattern: function [output] = name(input) ... end. We use cosd and sind so the angle is in degrees, and we suppress the echo with a trailing semicolon. The continuation ... is purely cosmetic — it lets the code look like the matrix we wrote on paper.

With this saved as RotaX.m, calling Rx = RotaX(30) gives the rotation matrix for 30°. Change the angle, call it again — no copy-paste, no rewriting.

Common gotcha: the output variable named in the function line must also be assigned inside the body. If you write function [Rx] = RotaX(T) then your matrix must be assigned to Rx, not to something else.
Name collision
If MATLAB complains that RotaX is both a function and a variable, run clear — you've left a stale variable in the workspace with the same name as your function.
RotaX.m — rotation about X by theta degreesmatlab
function [Rx] = RotaX(T)
    Rx = [ 1      0           0       ; ...
           0   cosd(T)   -sind(T) ; ...
           0   sind(T)    cosd(T) ];
end
§ 9

Extracting the mobile-frame vectors from Rx

To draw the rotated frame we need each mobile unit vector as separate $x$, $y$, $z$ components. Each entry of $R_x$ already holds one projection — we just pull them out by matrix index.

Reading $R_x$ column by column: column 1 is $\vec{u}$, column 2 is $\vec{v}$, column 3 is $\vec{w}$. So Rx(1,1) is $u_x$, Rx(2,1) is $u_y$, Rx(3,1) is $u_z$, and so on across the other two columns.

Once you have $u_x, u_y, u_z, v_x, v_y, v_z, w_x, w_y, w_z$, the three line calls for the mobile frame look exactly like the ones for the fixed frame — but the endpoints are these extracted values instead of literal 1s and 0s.

Index convention
MATLAB is (row, column). The $u$ vector is the first column, so its components are at rows 1, 2, 3 of column 1 — not row 1, columns 1–3.
pulling components out of Rxmatlab
ux = Rx(1,1);  uy = Rx(2,1);  uz = Rx(3,1);
vx = Rx(1,2);  vy = Rx(2,2);  vz = Rx(3,2);
wx = Rx(1,3);  wy = Rx(2,3);  wz = Rx(3,3);
