§ 03

Degrees of freedom and reference frames

To say a body is moving, we need something static to compare it against. So we attach a reference frame — three axes $x$, $y$, $z$ — to a stationary point (typically the robot's base).

A free rigid body in 3D space has six degrees of freedom: three translational (along $x$, $y$, $z$) and three rotational (about $x$, $y$, $z$). If we also let it rotate about its own mobile frame as well as the fixed one, we can talk about up to 12 DOF in a richer description.

For a manipulator we'll usually carry two frames: frame 0 at the base (fixed) and a mobile frame at the tool. The whole point of the course is to express, mathematically, how the mobile frame relates to the fixed one as the links of the robot move.

Around vs. along

"Along $x$" is translation. "Around $x$" is rotation. Same axis, different motion — keep them straight or the matrices will bite you later.

§ 04

Projecting unit vectors — and meeting the identity matrix

Place the mobile frame $(u, v, w)$ directly on top of the fixed frame $(x, y, z)$, using unit vectors of length 1.

How much of $u$ lies along $x$? All of it — $1$. Along $y$? $0$ (they're perpendicular). Along $z$? $0$. Do the same for $v$ and $w$ and you get a matrix whose diagonal is all ones and everything else is zero — the identity matrix $I_3$.

This is the "no rotation" case: the mobile frame is perfectly aligned with the fixed one. Every more interesting orientation we'll write down is a deviation from this.

$$ I_3 \;=\; \begin{bmatrix} 1 & 0 & 0 \\ 0 & 1 & 0 \\ 0 & 0 & 1 \end{bmatrix} \;=\; \big[\, u \mid v \mid w \,\big]_{\text{(aligned)}} $$
Read each column as "where the mobile axis points, expressed in the fixed frame." That reading will save you a lot of grief later.
Sign and direction

A column like $(0, -1, 0)^T$ means the mobile axis lies along $-y$ of the fixed frame. The magnitude tells you length; the sign tells you direction.

Identity matrix — frames alignedtxt
          x   y   z
     u [  1   0   0 ]
     v [  0   1   0 ]
     w [  0   0   1 ]

§ 05

Deriving the rotation matrix about $X$

Now rotate the mobile frame about the $x$-axis by an angle $\theta$. The $u$ axis doesn't move — it's still glued to $x$ — so its column stays $(1, 0, 0)^T$.

The $v$ axis tilts: its adjacent projection onto $y$ is $\cos\theta$, its opposite projection onto $z$ is $\sin\theta$. The $w$ axis tilts the other way: it picks up a $-\sin\theta$ along $y$ and $\cos\theta$ along $z$.

Stack those three columns and you get the basic rotation matrix:

$$ R_x(\theta) \;=\; \begin{bmatrix} 1 & 0 & 0 \\ 0 & \cos\theta & -\sin\theta \\ 0 & \sin\theta & \cos\theta \end{bmatrix} $$
Adjacent gets cosine, opposite gets sine. If you used cosine for one component of a column, you cannot use cosine for the other — that's the whole game.
Watch the minus sign

The $-\sin\theta$ in row 2, column 3 is where most first-time mistakes hide. It's there because $w$'s projection onto $y$ falls on the negative side of the axis — magnitude $\sin\theta$, direction $-y$.

Sanity check

At $\theta = 0$, every $\cos$ is $1$ and every $\sin$ is $0$ — $R_x(0) = I_3$. At $\theta = 90°$, $v$ should land on $+z$ and $w$ on $-y$. Read the columns to confirm.

$R_x(\theta)$ — basic rotation about Xtxt
R_x(θ) =
  [ 1     0          0       ]
  [ 0   cos θ    -sin θ      ]
  [ 0   sin θ     cos θ      ]

§ 06

MATLAB: drawing the fixed frame

line takes three arrays — start/end for $x$, then $y$, then $z$. Three calls, one per axis. Then view(130, 30) so we're looking at the frame from a sensible angle, and we colour each axis: $x$ red, $y$ green, $z$ blue.

Writing those four lines every time gets old fast, so we save the whole thing as a script — call it fixframe — and from then on a single fixframe in the command window redraws the base frame.

Script vs. function

A script just replays the same code. A function takes arguments and returns values. We'll need the second kind in the next section.

fixframe.m — base reference framematlab
line([0 1],[0 0],[0 0],'Color','r','LineWidth',2);
line([0 0],[0 1],[0 0],'Color','g','LineWidth',2);
line([0 0],[0 0],[0 1],'Color','b','LineWidth',2);
view(130,30);

§ 07

MATLAB: $R_x(\theta)$ as a function

We can type the matrix out by hand every time we change $\theta$, or we can wrap it. A function takes the angle in, returns the matrix out, and we never write that block again.

Note the use of cosd / sind — these take degrees, which is what we typed at the command line. If you use cos / sin, MATLAB expects radians and you'll get wrong numbers without an error.

Once you start writing functions, MATLAB stops being a calculator and starts being a programming language. That's the shift this course needs you to make.
cosd vs cos

cosd(30) ≈ $0.866$. cos(30) ≈ $0.154$ — because 30 radians. Mixing these is the most common silent bug at this stage.

Naming

The output variable in the function line (Rx) must match the variable you assign to inside the body — otherwise MATLAB will tell you the function returned nothing.

rotax.m — rotation about X as a functionmatlab
function Rx = rotax(t)
    Rx = [ 1      0           0        ; ...
           0   cosd(t)   -sind(t)     ; ...
           0   sind(t)    cosd(t)     ];
end
Interactive · Playground

rotax(θ) playground — drive the mobile frame

§ 08

Pulling the rotated axes out of the matrix

Each column of $R_x(\theta)$ is one of the rotated mobile axes expressed in the fixed frame. To draw the new frame, we just need to pull those nine numbers out and feed them to line.

In MATLAB, matrix entries are indexed Rx(row, col). So $u$'s $y$-component is Rx(2,1), $v$'s $z$-component is Rx(3,2), and so on. Once we have $u_x, u_y, u_z, v_x, v_y, v_z, w_x, w_y, w_z$ as scalars, drawing the rotated frame is three more line calls — exactly like fixframe, but with these values as the endpoints.

Column = axis

Column 1 of $R_x$ is where $u$ now points. Column 2 is where $v$ points. Column 3 is where $w$ points. Keep that mental model and the indices stop feeling arbitrary.

Extracting the nine componentsmatlab
theta = 30;
Rx = rotax(theta);

ux = Rx(1,1);  uy = Rx(2,1);  uz = Rx(3,1);
vx = Rx(1,2);  vy = Rx(2,2);  vz = Rx(3,2);
wx = Rx(1,3);  wy = Rx(2,3);  wz = Rx(3,3);
What the rotated frame should look likematlab
% Each line goes from the origin to the endpoint of
% the rotated mobile axis, expressed in the fixed frame.
line([0 ux],[0 uy],[0 uz],'Color','r','LineWidth',2);
line([0 vx],[0 vy],[0 vz],'Color','g','LineWidth',2);
line([0 wx],[0 wy],[0 wz],'Color','b','LineWidth',2);
