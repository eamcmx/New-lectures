§ 0

What this lecture covers

Two things. First: the rotation matrices we built last class describe motion around the fixed frame's axes — but a real robot, when you tell it "rotate around $z$," rotates around an axis parallel to fixed $z$ that passes through the mobile frame's origin. We need a tool that mimics that.

Second: given a transform $T^0_3$ that expresses frame $3$ in frame $0$, how do we write $T^3_0$ — the same physical relationship but with the reference flipped? We'll derive it by visual inspection, notice the rotation block is just the transpose, and end with the closed-form inverse of a homogeneous transformation matrix.

If today feels more like a puzzle than a lecture, that's deliberate — the point is the thinking, not the formula.

Today · two deliverables
What you'll walk out able to write
A function that rotates around the mobile-frame axes (for $x$, $y$, and $z$), and a function inverseT(M) that returns the inverse of a homogeneous transformation matrix — using the shortcut, not a generic 4×4 inverse.
§ 1

Where we left off — translating and rotating in two frames

We've been driving a mobile coordinate system with respect to a fixed base — call them frame $0$ (the base) and the moving frame attached to the tool. Translations along $x$, $y$, $z$ work cleanly in either frame: tell the matrix to translate along a chosen axis and the frame moves along the line you pointed at. No surprises.

Rotations around the mobile axes also behave the way the matrices predict. Rotate around mobile $x$ and the frame tips forward like a head nodding. Rotate around mobile $y$ and it yaws. Rotate around mobile $z$ and it spins about its own vertical. The frame follows the rotation — the axis travels with the body.

So for everything we've built so far, the matrix and the geometry agree. That agreement is what makes the next observation so jarring.

Mental model
Where each axis lives
Mobile-axis rotations follow the frame — the axis you spin about is attached to the body and moves with it. Fixed-axis rotations should pivot around the world origin — that's the part we're about to test, and the part that will surprise you.

§ 2

The discrepancy — what the real robot actually does

Now we ask the robot: rotate around the fixed $z$-axis. By the math, the tool should swing in a big arc around the base — picture it sweeping out a horizontal circle whose centre is the world origin. That is what $R_z(\theta)$ does to any point: it pivots that point about the line $z_0$.

The robot doesn't do that. It spins in place.

Look closely and you can see what's happening: the robot is rotating around an axis that is parallel to fixed $z$, but passing through the origin of the mobile frame — the tool. Same story for $x$ and $y$: the rotation axes are parallels of the world axes, anchored at the tool, not at the base.

So the matrix "rotate around world $z$" and the robot command "rotate around $z$" name the same direction, but choose different anchors. They are not the same operation. We need a matrix that mimics the robot's behaviour — one that pivots about the tool, not about the world.

The matrix says one thing, the robot does another — and the robot is not wrong. Our job is to describe what the robot actually does.

The gap
Direction vs. anchor
Fixed-frame rotation matrix → axis points along world $z$, pivots about the world origin. Robot "rotate around $z$" → axis parallel to world $z$, passes through the tool's current position. Same arrow, different anchor point.

§ 3

Today's exercise — derive the matrix that mimics the robot

The thinking task: assemble the transforms you already have to reproduce the robot's behaviour. You don't get to invent new matrices — only chain the elementary ones we already built. Here is the recipe we sketched on the board:

  1. Start at the fixed frame at the base.
  2. Translate along $x$ to move the mobile frame out to the tool's position.
  3. Translate along $z$ — "elevate" — to lift the mobile frame to the tool's height.
  4. Rotate the mobile frame $45°$ around one of its own axes, then $45°$ around another, to orient it like the tool.
  5. Now perform the rotation — around one of the resulting mobile axes (which is parallel to world $x$, $y$, or $z$, but anchored at the tool).

The key insight: position the mobile frame first, then rotate. Once the mobile frame sits at the tool, a rotation expressed in that mobile frame is exactly the rotation the robot performs — a spin around an axis through the tool, parallel to the requested world axis. The robot doesn't need a carobka (a linear carriage) to do this — the chain of transforms does it for you.

Compositionally: if $T_\text{current}$ is the current pose of the mobile frame and $R_\text{axis}(\theta)$ is the elementary rotation from last class embedded as a 4×4, then

$$T_\text{new} = T_\text{current} \cdot R_\text{axis}(\theta).$$

Multiplying $R_\text{axis}$ on the right is what makes the rotation act in the mobile frame instead of the fixed one. Multiply it on the left and you're back to a rotation about the world origin — the very thing we are trying to escape.

Position first, then rotate. That ordering is the whole trick.

Why this works
The geometry behind the chain
Once the mobile frame sits at the tool with the correct orientation, its own axes are parallel to (or aligned with) the world axes. A rotation expressed in that mobile frame is therefore a rotation about an axis through the tool, parallel to the requested world axis — which is exactly what the robot is doing.

§ 4

Changing the reference frame — from $T^0_3$ to $T^3_0$

Now the second problem. We have the transform that expresses frame $3$ in frame $0$ — that is, "how frame $3$ looks from the point of view of frame $0$":

$$T^0_3 = \begin{bmatrix} 0 & 1 & 0 & 5 \\ 0 & 0 & -1 & 4 \\ -1 & 0 & 0 & 3 \\ 0 & 0 & 0 & 1 \end{bmatrix}.$$

The columns of the top-left $3\times 3$ block are the mobile axes $x_3, y_3, z_3$ written in frame $0$. The fourth column $(5,\,4,\,3)^T$ is the position $p$ of frame $3$'s origin in frame $0$. The bottom row $[0\,0\,0\,1]$ makes the whole thing a homogeneous transform.

We want the opposite — frame $0$ expressed in frame $3$, i.e. $T^3_0$. Same physical setup; the geometry doesn't change. The only thing that changes is the reference: we are now standing at the tool and asking, where is the base, and how is it oriented, from here?

What changes
Reading the inverse matrix
The columns of the new rotation block will describe how the fixed axes $x_0, y_0, z_0$ look from the mobile viewpoint — and the new translation will describe where the world origin sits relative to the tool.
§ 5

Read off $T^3_0$ by visual inspection

Don't compute anything yet — just look at the axes. For each fixed-frame axis, ask: which mobile-frame axis does it lie along, and with what sign? That triple is one column of the new rotation block.

  • $x_0$ from frame $3$ is parallel to $y_3$. So column $1$ is $(0,\,1,\,0)^T$.
  • $y_0$ from frame $3$ is parallel to $-z_3$. So column $2$ is $(0,\,0,\,-1)^T$.
  • $z_0$ from frame $3$ is parallel to $-x_3$. So column $3$ is $(-1,\,0,\,0)^T$.

Stack the columns into the new rotation block:

$$R_{\,3\to 0} = \begin{bmatrix} 0 & 0 & -1 \\ 1 & 0 & 0 \\ 0 & -1 & 0 \end{bmatrix}.$$

Now compare it to the rotation block of the original $T^0_3$:

$$R_{\,0\to 3} = \begin{bmatrix} 0 & 1 & 0 \\ 0 & 0 & -1 \\ -1 & 0 & 0 \end{bmatrix}.$$

It's the transpose. Rows became columns, columns became rows. The orientation part of the inverse is just $R^T$.

This is the moment to notice that inverting a rotation matrix is free — no determinant, no cofactors, just flip it across the diagonal.

Identity · free inverse
Rotation block of $T^{-1}$
For any rotation matrix $R$ (orthonormal columns), $R^{-1} = R^T$. The columns of $R$ are unit vectors that are pairwise perpendicular, so $R^T R = I$ by inspection of every dot product. The rotation part of the inverse transform is therefore just the transpose of the rotation part of the original.

§ 6

What about the translation column?

The translation column is not just copied over. Two things have to happen to the original $p = (u,\,v,\,w)^T$:

  1. Express it in the new frame's coordinates — multiply by $R^T$.
  2. Flip its direction — multiply by $-1$.

Work it out by multiplying the transposed rotation by the original position $p = (5,\,4,\,3)^T$, row by row:

$$R^T p = \begin{bmatrix} 0 & 0 & -1 \\ 1 & 0 & 0 \\ 0 & -1 & 0 \end{bmatrix} \begin{bmatrix} 5 \\ 4 \\ 3 \end{bmatrix} = \begin{bmatrix} 0\cdot 5 + 0\cdot 4 + (-1)\cdot 3 \\ 1\cdot 5 + 0\cdot 4 + 0\cdot 3 \\ 0\cdot 5 + (-1)\cdot 4 + 0\cdot 3 \end{bmatrix} = \begin{bmatrix} -3 \\ 5 \\ -4 \end{bmatrix}.$$

Now multiply the whole column by $-1$:

$$-R^T p = \begin{bmatrix} 3 \\ -5 \\ 4 \end{bmatrix}.$$

That is the translation column of $T^3_0$. The new translation is $-R^T p$.

Sign matters
Why both pieces are needed
The minus sign is not cosmetic — it's the difference between "where is the tool from the base" and "where is the base from the tool." Opposite vectors. The $R^T$ on the outside then re-expresses that flipped vector in the tool's coordinate system. Skip either step and the answer is wrong.
§ 7

The closed form for the inverse

Putting both pieces together — transposed rotation block plus $-R^T p$ in the translation column — the inverse of a homogeneous transformation matrix is:

$$T^{-1} = \begin{bmatrix} R^T & -R^T\,p \\ 0\ \ 0\ \ 0 & 1 \end{bmatrix},$$

where $R$ is the $3\times 3$ rotation block and $p = (u,\,v,\,w)^T$ is the translation column of the original $T$. The bottom row stays $[0\ 0\ 0\ 1]$.

This is exactly what we mean by changing the frame of reference: same geometry, observed from the other side.

One transpose, one matrix-vector product, one sign flip. Cheaper than a general 4×4 inverse, and exact.

Why this beats inv(T)
Cost & numerical health
A general $4\times 4$ inverse costs around $64$ multiplications and can lose precision through cofactors and divisions. The homogeneous shortcut is one transpose (free), a $3\times 3$ matrix–vector product ($\approx 9$ multiplications), and three sign flips — exact, as long as $R$ stays orthonormal.
the worked example, both directions · txt
T^0_3 =  | 0  1  0   5 |        T^3_0 =  | 0  0 -1   3 |
         | 0  0 -1   4 |                 | 1  0  0  -5 |
         |-1  0  0   3 |                 | 0 -1  0   4 |
         | 0  0  0   1 |                 | 0  0  0   1 |

Sanity check (in your head, or on paper): multiply $T^3_0$ by $T^0_3$. The rotation block of the product is $R^T R = I$. The translation column is $R^T p + (-R^T p) = 0$. Bottom row is preserved. Result: the $4\times 4$ identity. Good.

§ 8

Code the inverseT function

Now turn the formula into a function. Signature: inverseT(T) takes a $4\times 4$ homogeneous transform and returns its inverse — using the shortcut, not a generic matrix inversion routine. The function should:

  1. Slice out the $3\times 3$ rotation block $R$ and the $3\times 1$ translation column $p$.
  2. Transpose $R$.
  3. Compute $-R^T p$.
  4. Reassemble the $4\times 4$ with $R^T$ in the top-left, $-R^T p$ as the translation column, and $[0\ 0\ 0\ 1]$ as the last row.

Test it on the worked example. inverseT(T) @ T must equal the identity (to numerical precision, say within $10^{-9}$). And the result of inverseT applied to $T^0_3$ must match the $T^3_0$ you derived by inspection.

Sanity check
If it's not the identity, where to look
If $T^{-1}T \ne I$, the bug is almost always one of three things: you forgot the minus sign on the translation; you transposed the whole $4\times 4$ instead of just the $3\times 3$ rotation block; or you computed $R\,p$ where you needed $R^T p$. Check those before anything more elaborate.
skeleton — fill in for your language of choice · py
def inverseT(T):
    R = T[0:3, 0:3]
    p = T[0:3, 3]
    Rt = R.T
    t  = -Rt @ p
    Tinv = np.eye(4)
    Tinv[0:3, 0:3] = Rt
    Tinv[0:3, 3]   = t
    return Tinv

§ 6

What about the translation column?

The translation column is not just copied over. Two things have to happen to the original $p = (u,\,v,\,w)^T$:

  1. Express it in the new frame's coordinates — multiply by $R^T$.
  2. Flip its direction — multiply by $-1$.

Work it out by multiplying the transposed rotation by the original position $p = (5,\,4,\,3)^T$, row by row:

$$R^T p = \begin{bmatrix} 0 & 0 & -1 \\ 1 & 0 & 0 \\ 0 & -1 & 0 \end{bmatrix} \begin{bmatrix} 5 \\ 4 \\ 3 \end{bmatrix} = \begin{bmatrix} 0\cdot 5 + 0\cdot 4 + (-1)\cdot 3 \\ 1\cdot 5 + 0\cdot 4 + 0\cdot 3 \\ 0\cdot 5 + (-1)\cdot 4 + 0\cdot 3 \end{bmatrix} = \begin{bmatrix} -3 \\ 5 \\ -4 \end{bmatrix}.$$

Now multiply the whole column by $-1$:

$$-R^T p = \begin{bmatrix} 3 \\ -5 \\ 4 \end{bmatrix}.$$

That is the translation column of $T^3_0$. The new translation is $-R^T p$.

§ 7

The closed form for the inverse

Putting both pieces together — transposed rotation block plus $-R^T p$ in the translation column — the inverse of a homogeneous transformation matrix is:

$$T^{-1} = \begin{bmatrix} R^T & -R^T\,p \\ 0\ \ 0\ \ 0 & 1 \end{bmatrix},$$

where $R$ is the $3\times 3$ rotation block and $p = (u,\,v,\,w)^T$ is the translation column of the original $T$. The bottom row stays $[0\ 0\ 0\ 1]$.

This is exactly what we mean by changing the frame of reference: same geometry, observed from the other side.

One transpose, one matrix-vector product, one sign flip. Cheaper than a general 4×4 inverse, and exact.

Why this beats inv(T)
Cost & numerical health
A general $4\times 4$ inverse costs around $64$ multiplications and can lose precision through cofactors and divisions. The homogeneous shortcut is one transpose (free), a $3\times 3$ matrix–vector product ($\approx 9$ multiplications), and three sign flips — exact, as long as $R$ stays orthonormal.

Sanity check (in your head, or on paper): multiply $T^3_0$ by $T^0_3$. The rotation block of the product is $R^T R = I$. The translation column is $R^T p + (-R^T p) = 0$. Bottom row is preserved. Result: the $4\times 4$ identity. Good.

§ 8

Code the inverseT function

Now turn the formula into a function. Signature: inverseT(T) takes a $4\times 4$ homogeneous transform and returns its inverse — using the shortcut, not a generic matrix inversion routine. The function should:

  1. Slice out the $3\times 3$ rotation block $R$ and the $3\times 1$ translation column $p$.
  2. Transpose $R$.
  3. Compute $-R^T p$.
  4. Reassemble the $4\times 4$ with $R^T$ in the top-left, $-R^T p$ as the translation column, and $[0\ 0\ 0\ 1]$ as the last row.

Test it on the worked example. inverseT(T) @ T must equal the identity (to numerical precision, say within $10^{-9}$). And the result of inverseT applied to $T^0_3$ must match the $T^3_0$ you derived by inspection.

Sanity check
If it's not the identity, where to look
If $T^{-1}T \ne I$, the bug is almost always one of three things: you forgot the minus sign on the translation; you transposed the whole $4\times 4$ instead of just the $3\times 3$ rotation block; or you computed $R\,p$ where you needed $R^T p$. Check those before anything more elaborate.
skeleton — fill in for your language of choice · py
def inverseT(T):
    R = T[0:3, 0:3]
    p = T[0:3, 3]
    Rt = R.T
    t  = -Rt @ p
    Tinv = np.eye(4)
    Tinv[0:3, 0:3] = Rt
    Tinv[0:3, 3]   = t
    return Tinv
