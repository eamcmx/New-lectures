Last time we got two coordinate frames living happily on top of each other, then nudged the mobile one around the X axis and watched the cosines and sines fall out. Today we make that motion move. We'll wrap the rotation matrix in a MATLAB function, drop it inside a for loop with hold on, clf, and drawnow, then repeat the whole exercise for Y and Z. By the end you'll have three rotation functions in your toolbox — and a first taste of moving a point from one frame to another.
§ 0

What this lecture covers

We pick up exactly where we left off: a fixed frame $\{x, y, z\}$, a mobile frame $\{u, v, w\}$, and the rotation matrix $R_x(\theta)$ that tells us where the mobile axes land after rotating around X. Today we turn that static matrix into a moving picture by looping over $\theta$ in MATLAB, and we generalise: build rotaY and rotaZ the same way. The lecture closes with the punchline that motivates everything else — given a point $A$ expressed in the mobile frame, multiplying by a rotation matrix gives us its coordinates in the fixed frame.

By the end you should be able to: write rotaX, rotaY, rotaZ from scratch; animate a rotating frame on top of a fixed one; and compute $A_{xyz} = R \cdot A_{uvw}$ for any axis.

If you didn't finish last week's program, please catch up before next class — this stack only goes up from here.

Prereq

You need the rotaX(T) function and a working drawSystem(R) plotter from Lecture 01. We're extending those, not rewriting them.

Heads up

MATLAB's cosd/sind take degrees. The whole lecture uses degree-based angles — don't mix in cos/sin (radians) by accident.

§ 1

Recap — rotation around X, in one matrix

When the mobile frame $\{u,v,w\}$ sits exactly on top of $\{x,y,z\}$, the relationship matrix is the identity $I_3$ — each axis is fully aligned with its partner, hence the 1s on the diagonal.

The instant we rotate around X by an angle $\theta$, the $u$ axis is unaffected (it's the axis of rotation), but $v$ and $w$ project onto $y$ and $z$ via cosines and sines. The result is the matrix below — every column is a mobile axis decomposed onto the fixed axes:

$$ R_x(\theta) \;=\; \begin{bmatrix} 1 & 0 & 0 \\ 0 & \cos\theta & -\sin\theta \\ 0 & \sin\theta & \cos\theta \end{bmatrix} $$
The rule of thumb: a 1 somewhere in the matrix forces zeros along its row and column. The rest is just which cathetus — adjacent gives cosine, opposite gives sine, and the sign comes from the right-hand rule.

Reading the matrix

Column 1 = where $u$ ended up (projected on $x$, $y$, $z$). Column 2 = where $v$ went. Column 3 = where $w$ went. That convention will hold for every rotation we build today.

R_x(θ) — rotation around the X axismatlab
R_x =
[ 1        0           0      ;
  0    cos(theta)  -sin(theta);
  0    sin(theta)   cos(theta) ]
rotaX.m — function form, degree-basedmatlab
function Rx = rotaX(T)
    Rx = [ 1        0           0       ;
           0    cosd(T)    -sind(T)   ;
           0    sind(T)     cosd(T)  ];
end

Drop the right symbol into each of the nine cells of $R_x(\theta)$. The 1 on the X-axis forces zeros along its row and column — everything else is a cosine, a sine, or its negative. Get it right and the matrix lights up green.

§ 2

Turning a matrix into three arrows — drawSystem

A rotation matrix is just numbers until we plot it. The trick: each column of $R$ is one axis of the mobile frame, expressed in the fixed frame. So column 1 is $(u_x, u_y, u_z)$, column 2 is $(v_x, v_y, v_z)$, column 3 is $(w_x, w_y, w_z)$.

We write a function that pulls out those nine components and draws three line segments from the origin to each tip. Semicolons at the end of every line keep the console clean — without them MATLAB echoes every assignment.

We renamed it from mobileSystem to drawSystem partway through class — the function doesn't care whether the matrix you pass in is the fixed frame ($I_3$) or a rotated one. Same code, both jobs.

Identity = fixed frame

Call drawSystem(eye(3)) to draw the fixed frame. The identity matrix's columns are exactly $\hat{x}$, $\hat{y}$, $\hat{z}$, so the function naturally draws the reference axes.

drawSystem.m — plot a frame from its rotation matrixmatlab
function drawSystem(R)
    ux = R(1,1); uy = R(2,1); uz = R(3,1);
    vx = R(1,2); vy = R(2,2); vz = R(3,2);
    wx = R(1,3); wy = R(2,3); wz = R(3,3);

    line([0 ux], [0 uy], [0 uz]);   % u axis
    line([0 vx], [0 vy], [0 vz]);   % v axis
    line([0 wx], [0 wy], [0 wz]);   % w axis

    view(45, 30);                   % elevation / azimuth
    axis equal; grid on;
end
Showing fixed + rotated at the same timematlab
I = eye(3);              % the fixed frame
Rx = rotaX(30);          % mobile frame rotated 30° around X

hold on
drawSystem(I);
drawSystem(Rx);

§ 3

Animating the rotation — for, hold on, clf, drawnow

Static is fine, but we want to watch the mobile frame swing through $\theta$. The recipe is a four-line dance:

  • for T = 0:0.1:60 — step the angle from 0° to 60° in 0.1° increments.
  • clf — clear the figure at the top of every iteration so we don't smear ghost arrows across the screen.
  • Draw the fixed frame, then drawSystem(rotaX(T)) for the mobile one.
  • drawnow — force MATLAB to render this frame before computing the next, instead of batching all 600 plots until the loop ends.

Leave out clf and you get a fan of footprints. Leave out drawnow and the figure freezes until the very end — MATLAB will happily compute the whole animation in silence and only show you the final pose.

In MATLAB the for header is the iterator. You don't increment $T$ yourself like in C — 0:0.1:60 is already the full list of values. Use a while loop if you want to bump the variable by hand.

Common bug

If your animation only shows one snapshot, you forgot drawnow. If it leaves trails, you forgot clf. Those two go together.

Step size

0:10 increments by 1° per frame — jumpy. 0:0.1:10 is smooth but slow. Pick the step to match how fast you want the animation to play.

exercise1.m — animate a frame rotating around X from 0° to 60°matlab
close all

I = eye(3);

for T = 0:0.1:60
    clf
    hold on
    drawSystem(I);            % fixed frame
    Rx = rotaX(T);
    drawSystem(Rx);           % mobile frame at angle T
    drawnow
end
▸ Try it · debug-the-loop

Which line did you forget — clf or drawnow?

Same for loop, four possible variants — pick one and play it back. You'll see the smear when clf is missing, the freeze-then-snap when drawnow is missing, and the smooth animation when both are in place. The fourth variant is the working code.

§ 4

Rotation around Y — building rotaY

Now $v$ is the axis of rotation, so the middle column is $(0, 1, 0)$ and the middle row is $(0, 1, 0)$. The remaining four corners carry the cosines and sines — but the sign pattern flips relative to $R_x$. Using the right-hand rule, a positive rotation around Y pushes $u$ down toward $-z$ and lifts $w$ up toward $+x$:

$$ R_y(\theta) \;=\; \begin{bmatrix} \cos\theta & 0 & \sin\theta \\ 0 & 1 & 0 \\ -\sin\theta & 0 & \cos\theta \end{bmatrix} $$

That asymmetry shows up as $+\sin\theta$ in the top-right and $-\sin\theta$ in the bottom-left — the opposite arrangement from $R_x$. This catches everyone the first time; if your animation rotates the wrong way, swap those two signs.

Lazy is good here — copy rotaX.m, rename, change only the cells that move. We'll do the same trick for rotaZ.

Sign trap

$R_y$ has $+\sin\theta$ in the (1,3) slot and $-\sin\theta$ in (3,1). $R_x$ and $R_z$ both put the negative sine in the top-right. Y is the odd one out — don't memorise by analogy.

R_y(θ) — rotation around the Y axismatlab
R_y =
[  cos(theta)   0    sin(theta);
      0        1        0     ;
  -sin(theta)   0    cos(theta) ]
rotaY.mmatlab
function Ry = rotaY(T)
    Ry = [  cosd(T)   0    sind(T) ;
               0      1       0    ;
           -sind(T)   0    cosd(T) ];
end
exercise2.m — animate around Ymatlab
close all
I = eye(3);

for T = 0:0.1:60
    clf
    hold on
    drawSystem(I);
    drawSystem(rotaY(T));
    drawnow
end

§ 5

Rotation around Z — building rotaZ

Last of the trio. Now $w$ is the axis of rotation, so the bottom-right is $(0, 0, 1)$ and the bottom row / right column are zeros except for that anchor. The top-left $2 \times 2$ block is the familiar planar rotation that you'd write for spinning a 2D arrow:

$$ R_z(\theta) \;=\; \begin{bmatrix} \cos\theta & -\sin\theta & 0 \\ \sin\theta & \cos\theta & 0 \\ 0 & 0 & 1 \end{bmatrix} $$

Sign-wise, $R_z$ matches $R_x$: $-\sin\theta$ top-right of the active block, $+\sin\theta$ bottom-left. Same for / clf / drawnow loop as before — just swap rotaX for rotaZ.

Three rotations done. Every subsequent rotation in this course — Euler angles, RPY, tool-plate orientation — is going to be products of these three. They're load-bearing.

The pattern

$R_x$, $R_y$, $R_z$ each protect one axis (the one you're rotating around) and apply a 2D planar rotation to the other two. Once you see that, you never have to memorise the matrices again.

R_z(θ) — rotation around the Z axismatlab
R_z =
[ cos(theta)  -sin(theta)   0;
  sin(theta)   cos(theta)   0;
      0            0        1 ]
rotaZ.mmatlab
function Rz = rotaZ(T)
    Rz = [ cosd(T)  -sind(T)   0 ;
           sind(T)   cosd(T)   0 ;
              0         0      1 ];
end

§ 6

Transforming a point — $A_{xyz} = R \cdot A_{uvw}$

Now the payoff. Imagine a point $A$ glued to the mobile frame — say at $A_{uvw} = (0.3, 0.4, 0.5)$. While the frames are aligned, its coordinates in the fixed frame are also $(0.3, 0.4, 0.5)$. The moment you rotate the mobile frame around X, $u, v, w$ tilt — and so does $A$ along with them.

The question "where is $A$ in the fixed frame now?" has a one-line answer:

$$ A_{xyz} \;=\; R_x(\theta) \cdot A_{uvw} $$

That's a $3 \times 3$ matrix times a $3 \times 1$ vector — output is $3 \times 1$, the new fixed-frame coordinates. Same formula works for Y and Z. This single operation is the atom that will eventually let us track a tool tip through every joint of a robot.

This is the moment the course pivots. Up to here we've been rotating frames. From now on we'll be rotating things — points on a gripper, axes of a joint, the tool plate itself. The matrix doesn't care which.

Mental model

$R_x(\theta) \cdot A_{uvw}$ says: "take $A$'s coordinates inside the mobile frame and re-express them using the fixed frame as the yardstick." The point hasn't moved through space — we've changed how we describe it.

Dimension check

$(3 \times 3) \cdot (3 \times 1) = (3 \times 1)$. If MATLAB throws Inner matrix dimensions must agree, you wrote $A$ as a row vector — transpose it.

Compute A in the fixed frame after a −30° rotation around Xmatlab
A_uvw = [0.3; 0.4; 0.5];     % column vector — important!

Rx    = rotaX(-30);
A_xyz = Rx * A_uvw

% A_xyz =
%     0.3000
%     0.5964
%    -0.2330

Animate the point $A$ riding the mobile frame

Pin a point at $A_{uvw} = (0.3, 0.4, 0.5)$ and watch what happens to its fixed-frame coordinates as you rotate. The vector $A_{uvw}$ never changes — it's glued to the mobile frame — but $A_{xyz} = R \cdot A_{uvw}$ recomputes each frame, and the marker sweeps through space along with $u, v, w$. This is the atom the rest of the course is built on.
