The Turing Machine — the computer that exists only on paper

In 1936 Alan Turing imagined the simplest possible computer — an endless tape, a read/write head, and a table of rules — not to build it, but to prove what any machine could ever compute. Write rules in the table below, press ▶ Run, and watch the tape do arithmetic.

The Machine

1936 · Alan Turing · zero hardware

Defined in the paper “On Computable Numbers, with an Application to the Entscheidungsproblem.” Not a physical machine — a thought experiment made of an infinite tape of cells, a read/write head, and a finite table of rules. That’s it. And that, Turing argued, is everything: it defines what “computable” means.

How it was “programmed”

You write the state-transition table: “in state q, reading symbol s — write this, move left or right, go to that state.” Every program ever written is, deep down, such a table. Turing even described a universal machine that reads another machine’s table off the tape and runs it — program as data, on paper, in 1936.

What it actually solved

No physical problem at all. It solved the question of what problems machines can solve — and proved some can’t be: the Entscheidungsproblem (a general procedure to decide mathematical truth) got its answer, and the answer was no. The universal machine became the theoretical blueprint for the stored-program computer.

Aside — the Universal Machine

Everything above is one machine per problem: one table adds, another increments. Turing’s deepest move was a machine U whose tape contains another machine’s rule table, written out as symbols — and U reads that description and behaves exactly like it. One fixed machine, any program. That is program-as-data, nine years before von Neumann’s 1945 stored-program memo turned it into hardware.

Notice what that means for the simulator you’re using: your rule table is just text in memory being interpreted by a fixed engine. You’ve been running a universal machine this whole time. See the hardware version in the Von Neumann machine simulator.

Simplifications — where we cheat

  • Turing’s 1936 formalism used m-configurations and allowed several prints and moves per step; we use the standard modern quintuple form — (state, read) → (write, move, next) — which is provably equivalent.
  • The tape really is unbounded here (cells are created as you wander), but the display is a window of about 21 cells that slides to keep the head centred. Infinity doesn’t fit on a screen.
  • We use □ as the blank symbol everywhere; busy-beaver literature calls the blank “0”. Same machine, different costume.
  • If two rules match the same (state, read), we flag them red and fire the first — a real Turing machine simply isn’t allowed to be ambiguous.
  • Real speed is meaningless for a paper machine, so the slider is purely for your eyes.

A control unit IS a rule table

State + symbol → action is all a CPU does too. The control unit takes an opcode plus flag bits (its “read symbol”), consults what is essentially a big transition table, and emits micro-operations (its “write and move”). When you edit the table above, you are doing microcode design with a pencil.

The universal machine is why software exists

One machine that runs any description means you never need new hardware for a new problem — just a new tape. One hardware, any program: that single 1936 idea is the entire premise of the stored-program computer, the operating system, and the app store.

Computability has limits

Turing proved no program can decide, for every program, whether it will halt. Watch the busy beaver: nothing about its six little rules tells you it stops at step 13 — you had to run it. Some problems aren’t hard. They’re impossible, and no amount of Moore’s Law will help.
