CISC vs RISC — two philosophies race

By the 1980s the field had split. CISC (Complex Instruction Set Computing — Intel's x86) said: make each instruction do a lot, even whole string searches, so programs are short. RISC (Reduced Instruction Set Computing — ARM, SPARC, PowerPC; Patterson & Ditzel's 1980 “The Case for the Reduced Instruction Set Computer”) said: make each instruction do almost nothing, so the hardware can pipeline them and the compiler can schedule them. Press ▶ Race and watch the same job compiled both ways.

The race — one task, two compilers

The task: load two numbers, multiply them, add a third, store the result — d = a·b + c. The CISC compiler emits 3 fat instructions; the RISC compiler emits 6 skinny ones. More instructions… yet watch who finishes first.

      First-order model, on purpose: real x86 timings vary wildly per instruction, and real pipelines have caches, branch predictors and deeper stages. The shape of the result — pipelining turns “more instructions” into “fewer total cycles” — is the honest part.

      Pipelines aren't free — the data hazard

      There's a catch the race hid from you. An instruction may need a value that the instruction right in front of it hasn't produced yet. Toggle the naive instruction order: ADD r5,r3,r4 ends up needing r4 the very cycle after LW r4,c loads it — and loaded data only arrives after the MEM stage. The pipeline must insert a bubble (a stall). Watch the race above change.

      Hazard off — compiler-scheduled order. The compiler hoisted LW r4,c up above the MUL, so nothing needs a loaded value on the very next cycle. Even the back-to-back MUL → ADD dependency is fine: forwarding wires pass the multiplier's output straight into the adder's input without waiting for write-back. Total: 10 cycles, zero stalls.

      Who won? — both, in a strange way

      x86 won the PC. Not because CISC was faster — because forty years of software already spoke x86, and compatibility is worth more than elegance.

      RISC won everything with a battery. ARM owns phones and embedded devices, and lately Apple's Macs and a growing share of cloud servers — simple instructions per joule is a winning currency.

      And inside a modern x86 chip? Both at once. The decoder takes each complex x86 instruction and chops it into RISC-like micro-ops, which flow into a pipeline just like the one that won the race. Watch it happen on the right.

      The resolution: the industry kept the CISC contract (your old software still runs) and swapped in a RISC engine (the speed). That's the very first distinction this lecture drew — architecture (the instruction set you promise) versus organization (the machinery underneath) — quietly ending a war.

      A modern x86 core: one MAC-style instruction enters the decoder, splits into three micro-ops, and streams through the same 5-stage pipeline. CISC on the outside, RISC on the inside.

      The real fight: where does complexity live?

      CISC put the cleverness in silicon (a microcoded decoder); RISC pushed it into the compiler. Notice how the hazard vanished when the compiler reordered two instructions — no new hardware needed. Moving work to compile time is a trick architecture keeps rediscovering: VLIW machines, GPU shader compilers, and today's ML compilers all replay the same bet.

      Pipelining is the assembly line: throughput ≠ latency

      Look at any single row of the pipeline diagram: one instruction still takes all 5 stages — its latency never improved. But look down a column: five instructions in flight, one finishing every cycle. That's why 6 RISC instructions beat 3 CISC ones — you don't ship cars faster by building each car faster, you ship faster by never letting a station sit idle.

      An ISA is a contract, not an engine

      x86 the contract has survived some 45 years while the machinery beneath it changed completely — today it's a RISC-style micro-op engine wearing a CISC costume. This is why architecture (the promise to software) and organization (the implementation) are taught as different subjects: contracts must last decades; engines get replaced every few years.
